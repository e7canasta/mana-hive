This section covers the foundational contexts for security and accountability within the mana-hub system. `ctx-identidad` manages users, credentials, and sessions, while `ctx-auditoria` provides an append-only log of all significant mutations.

## 1. Identity Management (ctx-identidad)

`ctx-identidad` is a generic bounded context responsible for determining who can access the system and what capabilities they possess [docs/contextos/ctx-identidad.md3-7](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-identidad.md?plain=1#L3-L7) It encapsulates user entities, password hashing via Argon2id, and bearer session lifecycles [docs/funcional/casos-uso/ctx-identidad.md5-7](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/casos-uso/ctx-identidad.md?plain=1#L5-L7)

### 1.1 Domain Model and Invariants

The context is built around two primary aggregates:

- **User**: Represents an identity with a unique normalized username, a display name, a `Role` (e.g., `supervisor`, `staff`), and a `PasswordHash` [docs/contextos/ctx-identidad.md20-23](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-identidad.md?plain=1#L20-L23)
- **Session**: Represents a temporal authorization. It only stores a SHA-256 hash of the bearer token; the clear-text token is never persisted [docs/contextos/ctx-identidad.md25-28](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-identidad.md?plain=1#L25-L28)

**Key Invariants:**

- **Username Uniqueness**: Usernames are normalized to lowercase and trimmed before checking uniqueness [docs/funcional/casos-uso/ctx-identidad.md13](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/casos-uso/ctx-identidad.md?plain=1#L13-L13)
- **Security Throttling**: `last_seen_at` in sessions is updated at most once per minute to reduce database write pressure [docs/funcional/contextos/ctx-identidad.md50-51](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/contextos/ctx-identidad.md?plain=1#L50-L51)
- **Logical Retirement**: Users are never hard-deleted. A `retired_at` timestamp blocks new sessions and invalidates existing ones [docs/contextos/ctx-identidad.md50-52](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-identidad.md?plain=1#L50-L52)

## 2. Capability-Based Authorization

Instead of checking roles directly in business logic, the system uses a **Capability** model. `ctx-identidad` derives an `AuthenticatedActor` which contains a set of effective capabilities [docs/funcional/modelo-dominio/ctx-identidad.md37-47](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/modelo-dominio/ctx-identidad.md?plain=1#L37-L47)

### 2.1 The AuthenticatedActor Read Model

The `AuthenticatedActor` is a non-persisted read model composed in memory by joining the `User`, their `Role`, and the globally enabled platform capabilities [docs/funcional/modelo-dominio/ctx-identidad.md42-45](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/modelo-dominio/ctx-identidad.md?plain=1#L42-L45)

## 3. Audit Logging (ctx-auditoria)

`ctx-auditoria` provides an append-only record of system activity. Every entry links an `actor_id` to an `action` performed on a specific `entity_type` and `entity_id` [crates/ctx-auditoria/src/domain.rs75-84](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-auditoria/src/domain.rs#L75-L84)

### 3.1 The Atomic Mutation-Audit Pattern

To ensure the audit log is truthful, mutations in `mana-app` follow a transactional pattern where the business change and the audit record are committed in the same SQLite transaction.

## 4. Implementation Details

### 4.1 Token Hashing

When a user logs in, the system generates a random bearer token. This token is hashed using SHA-256 before being stored in the `auth_sessions` table [docs/contextos/ctx-identidad.md57](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-identidad.md?plain=1#L57-L57) During authentication, the incoming token from the `Authorization` header is hashed, and the database is queried for that hash [docs/funcional/casos-uso/ctx-identidad.md71-72](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/casos-uso/ctx-identidad.md?plain=1#L71-L72) This ensures that a database leak does not compromise active sessions.

### 4.2 Key Functions

- `IdentityStore::authenticate`: Validates a token hash and ensures the associated user is not retired [crates/mana-app/src/identidad.rs188-191](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-app/src/identidad.rs#L188-L191)
- `AuditStore::record_in_transaction`: Appends an entry to the log using an existing transaction handle [crates/ctx-auditoria/src/store.rs60-64](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-auditoria/src/store.rs#L60-L64)
- `authenticated_actor`: A helper in `mana-app` that resolves a token into an `AuthenticatedActor` with its derived capabilities [crates/mana-app/src/identidad.rs223](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-app/src/identidad.rs#L223-L223)
