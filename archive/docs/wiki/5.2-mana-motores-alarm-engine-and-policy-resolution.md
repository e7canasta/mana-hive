The `mana-motores` crate contains the **pure business logic** for the Hub's clinical decision-making. It is designed to be stateless and free of I/O, receiving hydrated data from the application layer and returning structured decisions. Its primary responsibility is to convert sensor observations into alerts and translate resident clinical evidence into alarm policy recommendations.

## 1. The Alarm Engine (`evaluar`)

The alarm engine is a pure function that determines if a `SensorEvent` (or a time-based sweep) should result in a new alert. It enforces deduplication to ensure that repeated detector states do not flood the system with redundant notifications.

### 1.1 Rule Classes

The system distinguishes between two fundamental behaviors defined in the `AlarmCatalog`:

|Class|Trigger|Description|Code Entity|
|---|---|---|---|
|**Transicion**|`SensorEvent`|Dispatched when a state change occurs (e.g., `bed_exit`). Uses a `confirm` timer to wait for stability.|`Class::Transition` [crates/mana-motores/src/catalogo/mod.rs147-148](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/catalogo/mod.rs#L147-L148)|
|**Permanencia**|Clock / Sweep|Dispatched when a state persists too long (e.g., `out_of_bed_dwell`). Uses a `dwell` timer for tolerance.|`Class::Dwell` [crates/mana-motores/src/catalogo/mod.rs149-150](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/catalogo/mod.rs#L149-L150)|

### 1.2 Sensitivity Calibration

Sensitivity is not a hardcoded threshold but a multiplier applied to the base timers defined in the catalog. This allows clinical staff to adjust how "nervous" a rule is without changing the underlying logic.

- **Factor**: Multiplies the delay (e.g., `low = 1.5x` wait time). [config/alarm-catalog.toml28-31](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/config/alarm-catalog.toml#L28-L31)
- **Floor**: A minimum safety duration to prevent "flickering" alerts. [config/alarm-catalog.toml33-36](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/config/alarm-catalog.toml#L33-L36)

### 1.3 Logic Flow

The `evaluar` function follows these invariants:

1. **Temporal Policy**: It must use the `PerfilEfectivo` that was valid at `occurred_at`, not the current one. [docs/especificacion/motor-de-alarmas.md84-86](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/especificacion/motor-de-alarmas.md?plain=1#L84-L86)
2. **Deduplication**: Alerts are deduplicated by **episode**. If a resident is already out of bed and an alert was fired, no new alert is created until the state resets to "in bed". [docs/especificacion/motor-de-alarmas.md92-96](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/especificacion/motor-de-alarmas.md?plain=1#L92-L96)
3. **Unassigned Beds**: If no resident is assigned, the engine falls back to a fixed bed policy. [docs/especificacion/motor-de-alarmas.md73](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/especificacion/motor-de-alarmas.md?plain=1#L73-L73)

## 2. Alarm Catalog and Policy Resolution

The `AlarmCatalog` is the "Source of Truth" for clinical parameters. It is stored as a TOML file (`config/alarm-catalog.toml`) to allow clinical adjustments without code redeployment.

### 2.1 Resolution Hierarchy (`PerfilEfectivo`)

The system resolves the "Effective Profile" for a resident by merging three layers in order of precedence:

1. **Preset**: The base configuration for the `RiskLevel` (Low/Medium/High). [crates/mana-motores/src/catalogo/mod.rs170](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/catalogo/mod.rs#L170-L170)
2. **Template**: Specific clinical patterns (e.g., "Post-Fall", "Dementia"). [crates/mana-motores/src/catalogo/mod.rs171](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/catalogo/mod.rs#L171-L171)
3. **Override (Custom)**: Manual adjustments made by staff for a specific resident. [crates/mana-motores/src/catalogo/mod.rs172](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/catalogo/mod.rs#L172-L172)

## 3. Recommendation Engine

The recommendation engine analyzes resident signals (falls, bed exits, walking speed) over a window of time to suggest an appropriate `RiskLevel`.

### 3.1 Signal Processing

- **None is not Zero**: If a signal (like `walking_speed_mps`) was never observed, it is treated as `None`. Treating it as `0` would unfairly penalize the resident's score. [crates/mana-motores/src/recomendacion/mod.rs24-27](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/recomendacion/mod.rs#L24-L27)
- **Weight Accumulation**: Multiple factors (e.g., a real fall vs. a declared fall risk) are merged into a single `FactorDeRiesgo` to avoid UI clutter. [crates/mana-motores/src/recomendacion/tests.rs131-153](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/recomendacion/tests.rs#L131-L153)

### 3.2 Scoring Bands

The engine applies `ReglaDeRiesgo` types defined in the catalog:

- **Banda**: Numeric thresholds (e.g., "> 3 exits per night"). [crates/mana-motores/src/recomendacion/mod.rs84-96](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/recomendacion/mod.rs#L84-L96)
- **Incidentes**: History of falls or severe events. [crates/mana-motores/src/recomendacion/mod.rs98-106](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/recomendacion/mod.rs#L98-L106)
- **Rasgo**: Declared attributes like "Wandering". [crates/mana-motores/src/recomendacion/mod.rs108-113](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/recomendacion/mod.rs#L108-L113)

## 4. Autopilot Engine

Autopilot decides if a recommendation can be automatically applied to a resident's profile without human intervention. It implements an **asymmetric safety policy**.

### 4.1 Action Logic

|Action|Condition|
|---|---|
|`Apply`|The recommendation increases the risk level and has sufficient evidence. [crates/mana-motores/src/autopilot.rs148-149](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/autopilot.rs#L148-L149)|
|`Propose`|The recommendation decreases the risk level (requires human confirmation). [crates/mana-motores/src/autopilot.rs150-154](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/autopilot.rs#L150-L154)|
|`Keep`|Already at the recommended level or currently in `cooldown`. [crates/mana-motores/src/autopilot.rs132-146](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/autopilot.rs#L132-L146)|
|`Skip`|Autopilot is disabled or evidence is below `minimum_signals_for_raise`. [crates/mana-motores/src/autopilot.rs126-142](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/autopilot.rs#L126-L142)|

## 5. Technical Implementation Details

### 5.1 Key Functions

|Function|File|Description|
|---|---|---|
|`evaluar`|`alarmas.rs`|The core alarm decision logic.|
|`recomendar`|`recomendacion/mod.rs`|Calculates risk score and level from signals.|
|`decidir`|`autopilot.rs`|Applies safety rules to recommendations.|
|`resolve_effective`|`catalogo/mod.rs`|Flattens layers into a single set of rules.|

### 5.2 Error Handling

The `CatalogError` enum handles issues during TOML parsing or invalid overrides, such as attempting to disable a "locked" rule like `fall`. [crates/mana-motores/src/catalogo/mod.rs16-34](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-motores/src/catalogo/mod.rs#L16-L34)
