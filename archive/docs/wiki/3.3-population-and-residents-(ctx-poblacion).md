The `ctx-poblacion` context is a **Support** context responsible for the census of residents, their admission/discharge lifecycle, dated clinical attributes, and the temporal history of bed assignments [docs/contextos/ctx-poblacion.md1-14](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-poblacion.md?plain=1#L1-L14) It serves as the authoritative record for _who_ is in the facility and _where_ they are located at any given time.

## Functional Scope and Invariants

This context maintains the resident lifecycle and enforces physical occupancy rules. Key domain invariants include:

- **1-to-1 Occupancy**: A resident can have at most one open assignment, and a bed can have at most one open assignment [docs/contextos/ctx-poblacion.md93-96](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-poblacion.md?plain=1#L93-L96)
- **Atomic Reassignment**: Creating a new assignment (a "move") atomically closes the previous open assignments for both the resident and the target bed in a single transaction [docs/contextos/ctx-poblacion.md97-98](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-poblacion.md?plain=1#L97-L98)
- **Discharge Mechanics**: Discharging a resident is a separate business action that closes any open bed assignment but does not delete the resident record [docs/contextos/ctx-poblacion.md100-102](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-poblacion.md?plain=1#L100-L102)
- **Temporal Ordering**: Assignment intervals must be ordered and cannot overlap for either the resident or the bed [docs/contextos/ctx-poblacion.md99](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-poblacion.md?plain=1#L99-L99)

### Context Boundaries

`ctx-poblacion` is decoupled from `ctx-residencia`. It treats `bed_id` as an opaque `BedRef` and relies on `mana-app` to validate that the bed exists in the facility hierarchy [crates/ctx-poblacion/src/lib.rs10-11](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-poblacion/src/lib.rs#L10-L11)

## Bed Assignments (Temporal Model)

Assignments are modeled as temporal intervals `[starts_at, ends_at)`. An "open" assignment has a `NULL` `ends_at` [docs/contextos/ctx-poblacion.md62](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-poblacion.md?plain=1#L62-L62)

### The Reassignment Transaction

When a resident is moved to a new bed, `mana-app` coordinates a transaction that performs the following:

1. **Validation**: Ensures the resident is `active` [crates/ctx-poblacion/src/asignaciones/sqlite.rs54](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-poblacion/src/asignaciones/sqlite.rs#L54-L54)
2. **Closure**: Closes the resident's current assignment (if any) and the target bed's current assignment (if any) using the `starts_at` timestamp [crates/ctx-poblacion/src/asignaciones/sqlite.rs63-68](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-poblacion/src/asignaciones/sqlite.rs#L63-L68)
3. **Creation**: Inserts a new `BedAssignment` row [crates/ctx-poblacion/src/asignaciones/sqlite.rs75-86](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-poblacion/src/asignaciones/sqlite.rs#L75-L86)
4. **Audit**: Records the change in `ctx-auditoria` [docs/funcional/casos-uso/ctx-poblacion.md149](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/casos-uso/ctx-poblacion.md?plain=1#L149-L149)

## Technical Implementation Details

### Repository Pattern

The context uses the `repo` pattern to abstract Diesel/SQLite logic. The `SqliteConnection` implements traits like `ResidentesRepo` and `AsignacionesRepo` [crates/ctx-poblacion/src/residentes/sqlite.rs59](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-poblacion/src/residentes/sqlite.rs#L59-L59) [crates/ctx-poblacion/src/asignaciones/sqlite.rs45](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-poblacion/src/asignaciones/sqlite.rs#L45-L45)

### Key Methods

- `assign_in_transaction`: Implements the complex logic of closing existing intervals before opening a new one [crates/ctx-poblacion/src/asignaciones/sqlite.rs46-93](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-poblacion/src/asignaciones/sqlite.rs#L46-L93)
- `discharge_in_transaction`: Updates the resident status and closes any open assignments atomically [crates/ctx-poblacion/src/residentes/sqlite.rs83-101](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-poblacion/src/residentes/sqlite.rs#L83-L101)
- `list_residents`: Supports filtering by name and returns a read model that often includes the current bed via `mana-app` joins [crates/ctx-poblacion/src/residentes/sqlite.rs103-120](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-poblacion/src/residentes/sqlite.rs#L103-L120)

### Database Schema: `resident_bed_assignments`

```
CREATE TABLE resident_bed_assignments (    id TEXT PRIMARY KEY,    resident_id TEXT NOT NULL,    bed_id TEXT NOT NULL,    starts_at TEXT NOT NULL,    ends_at TEXT,    created_at TEXT NOT NULL,    created_by TEXT);
```

Partial unique indices (implemented via application logic and `latest` checks in the repository) ensure that for any `resident_id` or `bed_id`, only one row exists where `ends_at IS NULL` [docs/contextos/ctx-poblacion.md67-69](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/ctx-poblacion.md?plain=1#L67-L69)
