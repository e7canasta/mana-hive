Here is a thorough summary of each module in the `platform` directory:

## 1. `domain-kernel` -- The Pure Domain Foundation

**Build config:** Uses a `manahive.pure-domain` plugin (no external dependencies).

**Source files (4):**

| File | Purpose |
|------|---------|
| `Decider.kt` | Defines the core `Decider<C, S, E>` interface -- the universal shape of every event-sourced aggregate. It exposes two pure functions: `decide` (command + state -> events) and `evolve` (state + event -> new state). Also defines the `Decision` sealed type (`Accepted` with a list of events, or `Rejected` with a `RejectionReason`). |
| `Engine.kt` | Defines the `Engine` interface -- a pure domain service that must produce identical output for identical input (no Spring, no IO, no `Instant.now()`). Includes `EngineVersion` (name + semver + build fingerprint), `Explained<T>` (every output carries its reasoning), `ExplanationStep`, and `Discard` with a rich `DiscardCause` enum (illegal transition, confidence too low, hysteresis not met, duplicate, no occupant, staff present, episode already alerted, fatigue budget exceeded). |
| `DecisionRecord.kt` | A durable trace of one engine invocation -- the audit record that answers "why did the alarm (not) ring at 03:12?" It carries the engine version, stimulus reference, input fingerprints, output, explanation steps, discards, and timing. This is judgment telemetry, not business fact. |
| `Ids.kt` | Zero-cost strongly-typed identity value classes: `BedId`, `ResidentId`, `MonitorId`, `StaffId`, `AlertId`, `RuleId`, `EpisodeId`, and `NightId` (accounting period per bed per night). Also `EventRef` (stream + sequence pointer into the bus or ledger). The compiler prevents mixing IDs; there is zero runtime cost. |

**Role:** This is the heart of the domain model -- completely pure, no framework dependencies. It defines the event-sourcing contract (`Decider`), the engine service contract, the decision audit trail, and all domain identity types. Everything else in the system depends on this module.

## 2. `contracts` -- The Domain Language & Event Catalog

**Build config:** Uses `manahive.pure-domain`, depends on `projects.platform.domainKernel`.

**Source files (7):**

| File | Purpose |
|------|---------|
| `EventEnvelope.kt` | The wire envelope for every event on the bus. Carries `eventId` (idempotency key / NATS MsgId), `type`, `version`, `occurredAt`, `source`, and `payloadJson`. Schemas are versioned externally; events are API-forever (breaking changes produce new types, never mutations). |
| `perception/Observation.kt` | What the edge (ia-cell / camera) claims to have seen, translated from hardware to domain vocabulary. Carries `sourceEventId`, `monitor`, `bed`, `kind` (IN_BED, BED_EDGE, STANDING, OUT_OF_ROOM, STAFF_IN_ROOM, HEARTBEAT, UNCLASSIFIED), `confidence` [0,1], and `observedAt`. Published on `perception.observation.v1.<bed>`. |
| `scene/PersonState.kt` | A 5-state finite state machine for the person in the room: `Lying`, `BedEdge`, `Standing`, `Absent`, `Unknown` (with cause: SIGNAL_LOST or SCENE). Includes `StateKind` enum for wire format, and `RiskGroup` (SAFE, AT_RISK, UNKNOWN) derived from state. The comment "absence of information is not information" is key -- Unknown distinguishes a lost resident from a dead sensor. |
| `scene/SceneFact.kt` | The language the sentinel judges against policies. A sealed hierarchy of 8 fact types: `NightOpened` (opening entry for replay), `TransitionDetected`, `DwellWarning` (~80% threshold), `DwellExceeded`, `StaffPresenceDetected`, `SignalLost`, `SignalRecovered`, and `NightClosed` (with a `NightSummary`). Published per bed on `scene.fact.v1.<bed>`. |
| `sentinel/SentinelSignal.kt` | What the sentinel distilled from a scene fact under effective rules. Three variants: `IncidentDeclared` (needs a human NOW), `OccurrenceNoted` (recorded for round digest), `SuppressedWithRecord` (alarm suppressed but fact preserved with proof). Every signal carries the `rulesFingerprint` for reproducibility. Published on `sentinel.signal.v1.<bed>`. Includes `Severity` (INFO, WARNING, CRITICAL) and `SuppressionCause`. |
| `alarm/AlarmEvent.kt` | The full alert lifecycle, owned by the vigia. 8 event types: `AlertRaised`, `DeliveryOrdered`, `Delivered`, `Seen`, `Acknowledged`, `Escalated`, `Silenced` (requires expiry -- no permanent silence by type), `ResolvedByPresence` (measured, not declared), `ResolvedManually`. Deduplication by construction: one alert per (bed, rule, episode). |
| `census/CensusSnapshot.kt` | Who occupies which bed -- a read-only snapshot of bed-resident assignments. Distributed on `hub.census.snapshot.v1`. |
| `policy/EffectiveRules.kt` | The result of resolving layered policies (watch level -> template -> manual adjustments -> time windows) for one resident. Contains effective rules with kind (DWELL_LIMIT, NIGHT_EXIT, SIGNAL_WATCH), parameters, and provenance (which layer created it). Fingerprint is cited by all downstream decisions for reproducibility. |

**Role:** This module is the shared vocabulary (contracts) between all services. It defines every event type, every signal, every fact, and every identity used across the bus. It bridges the pure kernel types with the real-world domain concepts. It has no logic beyond data classes and enums -- it is the API boundary.

## 3. `messaging` -- The NATS Transport Layer

**Build config:** Uses `manahive.kotlin-common`, depends on `contracts` and `jnats` (NATS Java client) + `jackson-kotlin` for serialization.

**Source files (2):**

| File | Purpose |
|------|---------|
| `Subjects.kt` | A subject taxonomy for the NATS bus. Subject names are versioned (v1) and parameterized by domain IDs. Methods: `perceptionObservation(BedId)`, `sceneFact(BedId)`, `sentinelSignal(BedId)`, `alarmEvent(AlertId)`, `effectiveRules(ResidentId)`, `CENSUS_SNAPSHOT` (constant). Also defines wildcard subjects for stream subscription. The version-in-subject rule means breaking changes create new subjects; old consumers keep working. |
| `NatsTopology.kt` | Idempotent JetStream stream declaration. `ensureAll()` creates/updates 4 streams: PERCEPTION, SCENE, SENTINEL, ALARM -- each with a 7-day max age, file storage, limits-based retention, and a 10-minute duplicate window. Retention is intentionally limits-based: the bus is a transport buffer; the hub ledger is the system of record. First service to call `ensure()` wins; subsequent calls verify. |

**Role:** This module owns the transport infrastructure. It defines how events flow between services (the NATS subject hierarchy) and bootstraps the JetStream streams that carry them. It is the only module with external dependencies (NATS client, Jackson).

## System-Level Summary

The three `platform` modules together form the **backbone of an event-sourced healthcare monitoring system** (a "mana-hive") for monitoring residents in beds (nursing homes or similar). The data flow is:

1. **Perception** (edge cameras) produce `Observation` events
2. A scene engine digests those into `SceneFact` events (person state transitions, dwell times, staff presence)
3. A sentinel evaluates facts against `EffectiveRules` (policy) and emits `SentinelSignal` (incidents, occurrences, suppressions)
4. A vigia manages the `AlarmEvent` lifecycle (raise -> deliver -> escalate -> resolve)
5. The hub is the system of record, owns census and policy, and persists `DecisionRecord` audit trails

The domain kernel ensures pure, reproducible decision logic. Contracts ensure a stable, versioned API across all services. Messaging wires it all together on NATS JetStream.
