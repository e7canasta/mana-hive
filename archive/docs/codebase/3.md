## build-logic — Convention Plugins

**Purpose:** A Gradle included-build that houses three precompiled script plugins (convention plugins) shared across every module in the monorepo. All three inherit from a base plugin, forming a layered convention hierarchy.

### 1. `manahive.kotlin-common` (base layer)
- Applies `org.jetbrains.kotlin.jvm`.
- Pins JVM toolchain to **JDK 21**.
- Turns **all warnings into errors** and enables strict JSR-305 nullability annotations.
- Computes a fully-qualified archive name from the project path (e.g. `:engines:vigia:vigia-domain` becomes `engines-vigia-vigia-domain`), so nested modules never clash on artifact names.
- Configures all `Test` tasks to use JUnit Platform.

### 2. `manahive.pure-domain` (domain/kernel modules)
- Applies `manahive.kotlin-common`, then enforces **purity**:
    - Enables Kotlin `explicitApi()` — every public type must have an explicit visibility modifier.
    - Registers a `verifyPurity` task that **fails the build** if any non-Kotlin external dependency appears on the runtime classpath. Spring, JDBC, NATS, HTTP — all forbidden at the Gradle level. Fine-grained purity (e.g. banning `Instant.now()`) is left to Konsist in CI.

### 3. `manahive.spring-service` (Spring Boot services)
- Applies `manahive.kotlin-common` + the Kotlin Spring plugin + the Spring Boot plugin.
- Pulls in `spring-boot-dependencies` BOM (version from `libs.versions.toml`), `spring-boot-starter`, and `jackson-module-kotlin`.
- Adds `spring-boot-starter-test` for test scope.

## simulator — Night-Scenario Simulator

**Purpose:** A standalone Kotlin application (runs via `main()`) that defines **clinical night scenarios** — structured, time-ordered sequences of sensor observations and expected outcomes — for the mana-hive fall-detection/risk-monitoring system.

### Key files

| File | Role |
|---|---|
| `ScenarioDsl.kt` | A Kotlin DSL (`@DslMarker`) for declaring scenarios. A `Scenario` has a name, a start time, and a sorted list of `Step`s. Steps can be **Emit** (a sensor observation), **SensorGoesSilent**, or **Expect** (an acceptance criterion). The `Expectation` sealed hierarchy covers `AlertRaised`, `AlertEscalated`, `AlertResolvedByPresence`, `NoAlert`, and `SuppressedWithCause`. |
| `Scenarios.kt` | The scenario **bank** — three concrete scenarios built with the DSL: (1) **"the 03:00 fall"** — a standing observation, sensor silence, then critical alert escalation and staff resolution; (2) **"quiet night"** — bed-edge flicker absorbed by hysteresis, no alert expected; (3) **"staff present during risk transition"** — a standing observation while a nurse is in the room, alert suppressed with cause `STAFF_PRESENT`. |
| `Main.kt` | Entry point (`com.manahive.simulator.MainKt`). Currently prints every scenario's name and steps so clinicians can review the "canon." A later sprint will turn this into a full scenario runner with a virtual clock, in-memory transport, and expectation verification. |

### Dependencies
- `projects.platform.contracts` — provides domain types like `Observation`, `ObservationKind`, `BedId`, `MonitorId`.
- `projects.platform.messaging` — (declared but not yet used in the current source).

In short: the simulator is the **acceptance-test harness** for clinical safety rules. Each scenario is simultaneously a CI test, a golden-replay input, and a human-readable specification that clinicians can inspect before a rule is enabled.
