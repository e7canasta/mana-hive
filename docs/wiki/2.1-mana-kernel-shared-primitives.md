The `mana-kernel` crate serves as the zero-dependency foundation for the entire Hub System of Record. Its primary purpose is to define cross-cutting types and primitives that are used by all bounded contexts (`ctx-*`) and engine binaries without introducing business logic or domain-specific dependencies [crates/mana-kernel/src/lib.rs1](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L1-L1)

By design, `mana-kernel` only depends on fundamental utility libraries like `chrono`, `serde`, and `thiserror` [crates/mana-kernel/Cargo.toml7-10](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/Cargo.toml#L7-L10) This positioning at the bottom of the dependency graph ensures that common types can be shared across the workspace without creating circular dependencies.

## Strongly Typed Identifiers

To prevent the accidental interchange of IDs belonging to different entities (e.g., using a `ResidentId` where a `RoomId` is expected), `mana-kernel` implements a generic `Id<K>` wrapper.

### The `Id<K>` Structure

The `Id<K>` type wraps a `String` and uses a `PhantomData` marker `K` to differentiate types at compile time [crates/mana-kernel/src/lib.rs23-27](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L23-L27)

- **Creation**: IDs are created via `Id::new` or through `From<String>` implementations [crates/mana-kernel/src/lib.rs29-50](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L29-L50)
- **Serialization**: It implements `Serialize` and `Deserialize`, behaving as a plain string in JSON representations [crates/mana-kernel/src/lib.rs70-86](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L70-L86)
- **Safety**: The `define_kinds!` macro is used to generate empty enums that serve as markers for these IDs [crates/mana-kernel/src/lib.rs11-18](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L11-L18)

## Temporal Primitive: `Instante`

The `Instante` type provides a standardized way to handle time across the system. It enforces two strict invariants:

1. **UTC Normalization**: All timestamps are converted to UTC [crates/mana-kernel/src/lib.rs90-95](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L90-L95)
2. **ISO-8601 Formatting**: Serialization always uses the RFC3339 format with millisecond precision and the `Z` suffix [crates/mana-kernel/src/lib.rs122-126](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L122-L126)

`Instante` acts as a wrapper around `chrono::DateTime<Utc>` [crates/mana-kernel/src/lib.rs90](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L90-L90) It is used extensively in domain models for timestamps like `created_at`, `valid_from`, and `retired_at`.

## Error Vocabulary: `Fallo`

`Fallo` is an enumeration of shared error codes that define the contract between the Rust backend and external consumers (such as the legacy Node.js API or frontend clients) [crates/mana-kernel/src/lib.rs171-176](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L171-L176)

### Standard Variants

The vocabulary includes 12 standard variants, each mapping to a specific string code used in the wire protocol [crates/mana-kernel/src/lib.rs177-224](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L177-L224):

|Enum Variant|Wire Code|Description|
|---|---|---|
|`ValidationError`|`VALIDATION_ERROR`|Input data fails domain invariants.|
|`NotFound`|`NOT_FOUND`|The requested resource does not exist.|
|`Conflict`|`CONFLICT`|Unique constraint violation or state conflict.|
|`Forbidden`|`FORBIDDEN`|Authenticated but lacks required capabilities.|
|`Unauthenticated`|`UNAUTHENTICATED`|Missing or invalid session token.|
|`InternalError`|`INTERNAL_ERROR`|Unhandled server-side failure.|

### Error Flow and Propagation

Bounded contexts define their own error types (e.g., `HistoriaError`, `VigilanciaError`) using `thiserror`. These domain errors typically wrap `mana_storage::StorageError` and `diesel::result::Error` [crates/ctx-historia/src/error.rs7-22](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-historia/src/error.rs#L7-L22) [crates/ctx-vigilancia/src/error.rs4-15](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-vigilancia/src/error.rs#L4-L15) The application layer later maps these specific domain errors to the `Fallo` codes defined in `mana-kernel`.

## The Retirement Pattern

`mana-kernel` facilitates a "Soft Delete" or "Retirement" pattern used across the Hub. Instead of deleting rows, entities are marked as retired.

The kernel provides the `Actor` marker [crates/mana-kernel/src/lib.rs20](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L20-L20) and `Instante` [crates/mana-kernel/src/lib.rs90](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-kernel/src/lib.rs#L90-L90) which are used by context stores to implement:

- `retired_at`: An `Option<Instante>` indicating when the record was deactivated.
- `retired_by`: An `Option<Id<Actor>>` indicating which user performed the action.

This pattern is strictly enforced in the persistence layer of contexts like `ctx-residencia` and `ctx-poblacion` to maintain referential integrity and audit trails.
