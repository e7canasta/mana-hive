The `mana-engine-v2` is a stateful worker that maintains a real-time representation of the physical environment, known as the **DigitalTwin**. It transforms raw, discrete observations from edge cameras (**PerceptionEvents**) into a continuous, stateful model of residents and their surroundings, emitting enriched **SceneEvents** to the rest of the system [docs/reference/engine.md1-12](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/reference/engine.md?plain=1#L1-L12)

## System Context and Data Pipeline

The engine acts as the primary state machine between the raw sensor data and the rule evaluation logic. Unlike the Hub, which focuses on persistence and resolution, the Engine focuses on temporal state transitions and duration-based logic (dwells) [docs/contextos/observacion-v2.md33-38](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/contextos/observacion-v2.md?plain=1#L33-L38)

### Data Flow Overview

1. **Perception Ingest**: The Hub receives a POST from the Edge, resolves the `monitor_key` to a `bed_id`, and publishes to NATS `evt_perception` [docs/design/end-to-end-flow.md34-42](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/end-to-end-flow.md?plain=1#L34-L42)
2. **DigitalTwin Update**: The Engine consumes the perception event, updates its internal `BedTwin`, and evaluates FSM transitions [docs/design/end-to-end-flow.md44-52](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/end-to-end-flow.md?plain=1#L44-L52)
3. **Scene Emission**: The Engine publishes a `SceneEvent` to NATS `evt_scene`, which is consumed by the Sentinel for alarm evaluation and the Hub for projection updates [docs/design/end-to-end-flow.md54-67](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/end-to-end-flow.md?plain=1#L54-L67)

## DigitalTwin: The In-Memory State Model

The `DigitalTwin` is the top-level container that manages a collection of `BedTwin` objects, keyed by `bed_id` [crates/mana-engine-v2/src/digital_twin.rs111-115](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L111-L115) It functions like a PLC (Programmable Logic Controller), processing inputs in a loop and maintaining state in-memory rather than re-hydrating from a database for every event [docs/design/engine-digital-twin.md3-6](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-digital-twin.md?plain=1#L3-L6)

### BedTwin Components

Each `BedTwin` contains the complete state for a single bed area:

- **PersonTwin**: Current `PersonState`, `location`, and `state_since` timestamp [crates/mana-engine-v2/src/digital_twin.rs120-126](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L120-L126)
- **ObjectStates**: Occupancy/Presence for `bed`, `chair`, `wheelchair`, and `walker` [crates/mana-engine-v2/src/digital_twin.rs129-134](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L129-L134)
- **RoomTwin**: Resident, staff, and visitor counts [crates/mana-engine-v2/src/digital_twin.rs137-142](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L137-L142)
- **Timers**: Active dwell timers for the current state [crates/mana-engine-v2/src/digital_twin.rs161](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L161-L161)

## PersonState FSM

The Finite State Machine (FSM) governs the resident's status. States are categorized into logical groups to simplify rule evaluation [crates/mana-engine-v2/src/fsm.rs3-28](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/fsm.rs#L3-L28)

### State Classification

|Category|PersonState Variants|
|---|---|
|**In Bed**|`Lying`, `SittingInBed`, `BedEdge`|
|**Out of Bed**|`Standing`, `InBathroom`, `InRoom`, `InHallway`, `Outdoor`|
|**Furniture**|`InChair`, `InWheelchair`|
|**Other**|`Unknown`|

**Sources:** [crates/mana-engine-v2/src/fsm.rs9-28](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/fsm.rs#L9-L28) [docs/reference/engine.md41-49](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/reference/engine.md?plain=1#L41-L49)

### Transitions

Transitions occur in `on_perception_event`. When a new state is detected:

1. Existing timers for the **old state** are marked as `Cancelled` [crates/mana-engine-v2/src/digital_twin.rs62-66](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L62-L66)
2. The `state_since` timestamp is updated to the event's `occurred_at` [docs/design/engine-super-loop.md131-134](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-super-loop.md?plain=1#L131-L134)
3. New timers for the **new state** are initialized based on `DwellRules` [docs/design/engine-super-loop.md135-136](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-super-loop.md?plain=1#L135-L136)
4. A `SceneEvent` of type `Transition` is emitted [docs/design/engine-super-loop.md138-147](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-super-loop.md?plain=1#L138-L147)

**Sources:** [crates/mana-engine-v2/src/fsm.rs90-207](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/fsm.rs#L90-L207) [docs/design/engine-timers.md86-105](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-timers.md?plain=1#L86-L105)

## The PLC Super Loop (Tick)

The engine runs a "Super Loop" that executes a `tick()` function at a regular interval (default 5 seconds) [docs/design/engine-super-loop.md210-222](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-super-loop.md?plain=1#L210-L222)

### Tick Workflow

The `tick(now)` function iterates through all active `BedTwin` instances:

1. **Timer Evaluation**: For every `Timer` in `TimerState::Active`, it checks if `now - started_at >= threshold_minutes` [crates/mana-engine-v2/src/digital_twin.rs48-60](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L48-L60)
2. **Dwell Emission**: If a timer fires, it is marked as `Fired`, and a `SceneEvent` with `event_type: Dwell` is generated [crates/mana-engine-v2/src/digital_twin.rs205-235](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L205-L235)
3. **Cleanup**: After processing, `Fired` and `Cancelled` timers are removed from the `BedTwin` to prevent duplicate events [docs/design/engine-super-loop.md202-204](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-super-loop.md?plain=1#L202-L204)

## Dwell Timer Lifecycle

Dwell timers measure how long a resident remains in a specific state. Thresholds are defined in `DwellRules` [crates/mana-engine-v2/src/digital_twin.rs74-80](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L74-L80)

### Default Thresholds

- **out_of_bed**: 10 minutes
- **in_bed**: 300 minutes
- **standing**: 5 minutes
- **in_bathroom**: 30 minutes

**Sources:** [crates/mana-engine-v2/src/digital_twin.rs82-91](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/mana-engine-v2/src/digital_twin.rs#L82-L91) [docs/design/engine-digital-twin.md63-69](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-digital-twin.md?plain=1#L63-L69)

### Sensitivity Calibration

The `threshold_minutes` can be adjusted based on the resident's risk profile (sensitivity):

- **High**: 0.5x base duration
- **Standard**: 1.0x base duration
- **Low**: 1.5x base duration

**Sources:** [docs/design/engine-timers.md231-247](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-timers.md?plain=1#L231-L247)

## SceneEvent Structure

The `SceneEvent` is the primary output of the engine. It is an **immutable, self-contained snapshot** of the entire scene at a specific point in time [docs/specs/scene-event.md7-12](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/specs/scene-event.md?plain=1#L7-L12)

|Field|Description|
|---|---|
|`event_type`|`Perception`, `Dwell`, `Transition`, or `Change` [docs/specs/scene-event.md41-55](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/specs/scene-event.md?plain=1#L41-L55)|
|`trigger`|Metadata explaining why the event was emitted (e.g., `DwellCompleted` with duration) [docs/specs/scene-event.md59-87](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/specs/scene-event.md?plain=1#L59-L87)|
|`poi`|Person of Interest: includes `PersonState`, `location`, and `state_since` [docs/specs/scene-event.md91-100](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/specs/scene-event.md?plain=1#L91-L100)|
|`bed/chair/room`|The occupancy status of all monitored objects [docs/specs/scene-event.md161-183](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/specs/scene-event.md?plain=1#L161-L183)|

## Implementation Details: Ports and Adapters

The engine is designed to be "pure" (logic-only), using traits (ports) to interact with NATS and the Hub [docs/design/engine-ports.md3-9](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-ports.md?plain=1#L3-L9)

- **EngineInput**: Receives `PerceptionEvents` and triggers `tick()` [docs/design/engine-ports.md15-27](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-ports.md?plain=1#L15-L27)
- **EngineOutput**: Publishes `SceneEvents` to the event mesh [docs/design/engine-ports.md31-37](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-ports.md?plain=1#L31-L37)
- **TwinStore**: Handles persistence of the `DigitalTwin` state to `scene_states` table in SQLite to survive restarts [docs/design/engine-ports.md41-53](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/design/engine-ports.md?plain=1#L41-L53)
