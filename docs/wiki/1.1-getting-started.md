The **mana-hub** system is the primary System of Record (SoR) and Event Store for the Virtual Rounds ecosystem [docs/funcional/north-star.md1-4](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/north-star.md?plain=1#L1-L4) It is built as a modular monolith in Rust, managing 11 bounded contexts and coordinating three stateless worker binaries via a NATS JetStream event mesh [docs/arquitectura/memoria-diseno98-109](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/arquitectura/memoria-diseno#L98-L109)

## 1. Local Environment Setup

The system requires a Rust toolchain, SQLite, and a NATS server for full event-driven functionality.

### Prerequisites

- **Rust**: Latest stable version.
- **SQLite**: Used for the primary System of Record.
- **NATS Server**: Required for JetStream messaging (`nats-server -js`) [tests/e2e.sh60-62](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/tests/e2e.sh#L60-L62)
- **Just**: A task runner used to manage the binary lifecycle [just/justfile1-11](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/just/justfile#L1-L11)

### Environment Variables

Configuration is driven by environment variables, with defaults suitable for local development [README.md89-96](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/README.md?plain=1#L89-L96)

|Variable|Purpose|Default|
|---|---|---|
|`API_PORT`|Public HTTP port for `mana-hub`|`8780`|
|`API_HOST`|Network interface to bind|`0.0.0.0`|
|`MANA_HUB_DATABASE_URL`|Path to the SQLite database file|`hub.sqlite`|
|`MANA_HUB_SEED_DEMO`|If `1`, seeds demo users (`gaston`, `staff`)|`0` (disabled)|
|`NATS_URL`|NATS server connection string|`nats://127.0.0.1:4222`|
|`RUST_LOG`|Logging verbosity level|`info`|

## 2. Building and Running

The system uses the `just` task runner to simplify binary management and database operations.

### Basic Commands

```
# Build the main API and the CLI
just hub-build
 
# Start the Hub in the background
just hub-start
 
# Check status and health endpoints
just hub-status
 
# Stop the Hub
just hub-stop

```

## 3. Database and Migrations

The system employs a **decentralized migration strategy**. While `mana-hub` is the only binary that connects to SQLite, the migrations themselves are owned by each `ctx-*` crate [docs/arquitectura/memoria-diseno143-146](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/arquitectura/memoria-diseno#L143-L146)

- **Initialization**: When `mana-hub` starts, it executes all embedded migrations for every context [docs/funcional/modulos/mana-hub.md9-11](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/modulos/mana-hub.md?plain=1#L9-L11)
- **WAL Mode**: The database is configured in Write-Ahead Logging (WAL) mode for better concurrency [docs/reference/architecture.md31](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/reference/architecture.md?plain=1#L31-L31)
- **Resetting**: To wipe the local database and start fresh:
    
    ```
    just db-fresh
    ```
    
    This stops the hub, deletes `hub.sqlite` (and its `-wal`/`-shm` sidecars), and restarts the hub to trigger new migrations [just/hub.just77-83](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/just/hub.just#L77-L83)

## 4. Migration Status (`rutas.toml`)

The `rutas.toml` file serves as the source of truth for the API surface and the migration status from the legacy Node.js system [README.md47-50](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/README.md?plain=1#L47-L50)

- **Contract Enforcement**: Every route defined in `rutas.toml` must have a corresponding handler registered in `mana-http`. If a route is marked as `sirve = "rust"` but no handler is found, the `mana-hub` binary will refuse to start [README.md163-164](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/README.md?plain=1#L163-L164)
- **Status Endpoint**: The current progress of the migration can be viewed at: `GET http://localhost:8780/__hub/rutas` [README.md86](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/README.md?plain=1#L86-L86)

## 5. Testing and Validation

### Health Endpoints

The Hub provides standard endpoints for monitoring:

- `/health`: General liveness check [README.md84](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/README.md?plain=1#L84-L84)
- `/__hub/ready`: Readiness check (verifies DB and NATS connectivity) [README.md85](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/README.md?plain=1#L85-L85)

### Scene-Based Testing

The `mana-sdk` includes a scene runner that validates domain logic by loading JSON-defined scenarios [README.md69-75](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/README.md?plain=1#L69-L75)

```
# Validate a scenario without side effects
cargo run -p mana-sdk --bin mana -- scene validate --file=../scenes/identidad-smoke.json
 
# Load a scenario into the running Hub
cargo run -p mana-sdk --bin mana -- scene load --file=../scenes/identidad-smoke.json
```
