This page documents the operational lifecycle, health monitoring, and messaging resilience patterns of the `night-watch-runtime` service. Given the 24/7 nature of resident safety monitoring, the system distinguishes between the process being "alive" and the system being "operational" (connected to the messaging bus and actively monitoring).

## Runtime State Model

The service implements a state machine to track its operational readiness. Unlike standard services that might fail to start if dependencies are missing, the Night-Watch Runtime is designed to start in a disconnected state and wait indefinitely for the messaging bus (NATS), transitioning through various states as connectivity fluctuates.

### RuntimeState Transitions

The `RuntimeState` enum [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeStatus.kt14-29](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeStatus.kt#L14-L29) defines the following lifecycle:

|State|Description|
|---|---|
|`STARTING`|The Spring context is initializing.|
|`WAITING_FOR_BUS`|The process is up, but no NATS connection is established. No observations can be processed.|
|`RUNNING`|Connected to NATS and actively consuming observations.|
|`DEGRADED`|Was previously `RUNNING` but lost connection. The system is attempting to reconnect.|
|`STOPPED`|The service is shutting down.|

### Status Management

The `RuntimeStatusHolder` [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeStatus.kt46-58](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeStatus.kt#L46-L58) maintains an `AtomicReference` to the current `RuntimeStatus`, which includes the state, a timestamp (`since`), and a human-readable detail string. This allows external monitoring tools to determine exactly how long the system has been in a non-functional state.

## Bus Connectivity & Resilience

The `BusConnector` and `BusEvents` classes handle the interaction with the NATS infrastructure.

### BusConnector

The `BusConnector` [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/BusConnector.kt15-18](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/BusConnector.kt#L15-L18) uses `NatsConfig.connectAsync` to prevent the application startup from blocking if the NATS server is unavailable. It registers a `ConnectionListener` that updates the `BusEvents` object whenever the connection status changes [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/BusConnector.kt24-40](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/BusConnector.kt#L24-L40)

### BusEvents Resilience Pattern

To avoid deadlocks during Spring context initialization, the `BusEvents` class [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeStatus.kt77-95](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeStatus.kt#L77-L95) acts as a bridge between the NATS client threads and the Spring-managed beans. It uses `@Volatile` properties for callbacks (`onConnected`, `onLost`) and the `Connection` object itself. This ensures that the NATS listener can fire even while the `NightWatchService` bean is still being constructed.

### Topology Setup

The runtime relies on `NatsTopology.ensureAll` (provided by the `:platform:messaging` project) to ensure that the required NATS JetStream streams and consumers exist. This is typically invoked within the `onConnected` callback of `BusEvents`.

## Health Monitoring & API

The service exposes its internal state through both Spring Boot Actuator and a custom REST controller.

### NightWatchHealthIndicator

The `NightWatchHealthIndicator` [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt22-40](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt#L22-L40) integrates with Spring Actuator. It reports `UP` only if the state is `RUNNING` [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt30](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt#L30-L30) It provides rich metadata, including:

- **state**: The current `RuntimeState`.
- **bus**: The NATS connection status (e.g., `CONNECTED`, `RECONNECTING`).
- **residents**: The total number of residents currently being monitored by the `NightWatchRuntime`.
- **since**: The timestamp of the last state transition.

### RuntimeStatusController

For more granular monitoring, the `RuntimeStatusController` [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt49-77](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt#L49-L77) provides the `/api/runtime/status` endpoint.

**Data Flow: Status Aggregation**

The controller returns a `RuntimeStatusResponse` which includes a list of `ResidentStatusResponse` objects [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt79-93](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt#L79-L93) This allows operators to see:

1. **resident**: The Resident ID.
2. **bed**: The assigned Bed ID.
3. **openEpisodes**: Count of active episodes in the Sentinel Engine.
4. **dispatched**: Count of notices currently dispatched in the Harbor Engine.

If the system is not in a `RUNNING` state, the controller returns `HTTP 503 Service Unavailable` [engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt74-75](https://github.com/pbaalerta-wq/hisso1/blob/d9fca861/engines/night-watch-runtime/src/main/kotlin/com/manahive/runtime/RuntimeHealth.kt#L74-L75)

## Configuration

The service configuration is managed via `application.yml`.

### application.yml

The default configuration sets the server port and NATS connection URL.

```
spring:
  application:
    name: night-watch-runtime # [engines/night-watch-runtime/src/main/resources/application.yml:3]()
 
server:
  port: 8081 # [engines/night-watch-runtime/src/main/resources/application.yml:8]()
 
nats:
  url: nats://localhost:4222 # [engines/night-watch-runtime/src/main/resources/application.yml:11]()
 
logging:
  level:
    com.manahive.runtime: INFO # [engines/night-watch-runtime/src/main/resources/application.yml:15]()
```

### Dependencies

The `night-watch-runtime` module aggregates all four engines and the messaging infrastructure:

- **Engines**: `sceneDomain`, `sentinelDomain`, `harborDomain`, `recorderDomain`.
- **Infrastructure**: `platform:messaging`, `platform:serialization`, `politicaAdapters`.
- **Spring**: `spring-boot-starter-web`, `spring-boot-starter-actuator`.
