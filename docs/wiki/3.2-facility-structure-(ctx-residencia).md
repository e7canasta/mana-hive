The `ctx-residencia` context defines the physical hierarchy of the facility. It acts as the system of record for the environment where care operations occur, managing the relationship between facilities, wings, rooms, and beds, as well as their spatial configuration and privacy settings.

## Physical Hierarchy

The system enforces a strict four-tier hierarchy [docs/funcional/modelo-dominio/ctx-residencia.md10-17](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/modelo-dominio/ctx-residencia.md?plain=1#L10-L17) Each entity owns its lifecycle but maintains referential integrity via foreign keys within the SQLite schema [docs/funcional/modelo-dominio/ctx-residencia.md116-126](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/modelo-dominio/ctx-residencia.md?plain=1#L116-L126)

|Tier|Entity|Responsibility|Unique Constraint|
|---|---|---|---|
|1|**Facility**|Top-level residence with timezone configuration.|Name + Timezone|
|2|**Wing**|Orderable operational units (e.g., "North Wing").|Name within Facility|
|3|**Room**|Physical rooms linked to a `StreamKey` (camera).|Number within active Wing|
|4|**Bed**|Specific care locations linked to a `MonitorKey` (sensor).|MonitorKey across active beds|

### Entity Bindings: Stream and Monitor Keys

- **StreamKey**: Identifies a camera stream. A key can belong to at most one active room [docs/funcional/casos-uso/ctx-residencia.md20](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/casos-uso/ctx-residencia.md?plain=1#L20-L20)
- **MonitorKey**: Identifies a hardware sensor (e.g., radar). A key can belong to at most one active bed [docs/funcional/casos-uso/ctx-residencia.md21](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/casos-uso/ctx-residencia.md?plain=1#L21-L21)

## Spatial Layouts and Privacy

### Wing Planograms

The planogram defines the `(x, y)` coordinates of rooms within a wing for UI visualization [docs/funcional/modelo-dominio/ctx-residencia.md50-56](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/modelo-dominio/ctx-residencia.md?plain=1#L50-L56)

- **Versioned Replaced Pattern**: Saving a planogram marks all previous placements for that wing as `active = 0` and inserts new ones [crates/ctx-residencia/src/planograma/sqlite.rs91-113](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-residencia/src/planograma/sqlite.rs#L91-L113)
- **Validation**: Rooms must belong to the specified wing and cannot be duplicated in the same planogram [crates/ctx-residencia/src/planograma/sqlite.rs61-89](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-residencia/src/planograma/sqlite.rs#L61-L89)

### Privacy Regions

Defines masking rectangles for video streams to protect resident privacy.

- **Constraints**: Maximum of 8 regions per room (`MAX_PRIVACY_REGIONS`) [crates/ctx-residencia/src/privacidad/sqlite.rs60-65](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-residencia/src/privacidad/sqlite.rs#L60-L65)
- **Normalization**: Coordinates must be within `0.0` to `1.0` range [docs/funcional/modelo-dominio/ctx-residencia.md92-93](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/modelo-dominio/ctx-residencia.md?plain=1#L92-L93)
- **Storage**: Uses the same "deactivate and replace" pattern as planograms [crates/ctx-residencia/src/privacidad/sqlite.rs70-93](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-residencia/src/privacidad/sqlite.rs#L70-L93)

**Sources:** [crates/ctx-residencia/src/planograma/sqlite.rs55-115](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-residencia/src/planograma/sqlite.rs#L55-L115) [crates/ctx-residencia/src/privacidad/sqlite.rs53-95](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-residencia/src/privacidad/sqlite.rs#L53-L95) [docs/funcional/modelo-dominio/ctx-residencia.md50-64](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/modelo-dominio/ctx-residencia.md?plain=1#L50-L64)

## Cascade Retirement Pattern

The system uses a "logical retirement" pattern (`retired_at`, `retired_by`) instead of hard deletes [docs/funcional/modelo-dominio/ctx-residencia.md74](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/modelo-dominio/ctx-residencia.md?plain=1#L74-L74)

Title: Retirement and Validation Flow

- **Validation Rule**: A child cannot be created under a retired or non-existent parent [docs/funcional/casos-uso/ctx-residencia.md18](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/docs/funcional/casos-uso/ctx-residencia.md?plain=1#L18-L18)
- **Visibility**: Read models and lists automatically filter out retired entities using `.filter(table::retired_at.is_null())` [crates/ctx-residencia/src/estructura/sqlite.rs199-201](https://github.com/pbaalerta-wq/hubp/blob/cc2edd14/crates/ctx-residencia/src/estructura/sqlite.rs#L199-L201)
